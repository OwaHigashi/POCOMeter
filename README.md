# POCOMeter

Pococha のランクメーターの非公式予測ツールです。D1〜S6 の各ランクと 13 時・22 時・24 時の締め時間について、±0・+1・+2 に必要な応援ポイントの予測と、取得済みの公開実績を表示します。日付と締め時間は日本時間（JST）です。

## ローカルで動かす

Python 3.9 以降と PHP 8.1 以降が必要です。データの更新には Unix 系の環境と、外部のデータ取得元への接続が必要です。ランク別補正に LightGBM と NumPy を使うため、リポジトリのルートに仮想環境を作ってから実行します（`.venv` は Git の対象外で、`.htaccess` により Web からも見えません）。

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -B update_meter.py
php -S 127.0.0.1:8000
```

ブラウザーで `http://127.0.0.1:8000/` を開きます。更新スクリプトは予測と実績を `data.json` に、更新状況を `status.json` に保存します。`events.json` は手動で確認した公式イベント情報です。

取得した実績は `.meter-state.json` にすべて保存し、古いものも削除しません。毎回の更新では、締め時刻を過ぎた最新の日をまだ持っていない系列だけ、当月のページを1回ずつ取得し、新しい日と値が変わった日だけを追加します。最新の日まで保存済みの系列は取得しません（そのため、保存済みの日の値が後から訂正されても反映されません）。前月のページを取得するのは、月初5日までと初回構築のときだけです。

2026年8月以前（2022年6月〜）の実績は、LIVER CAMPUS（one-carat）の月別ボーダー早見表の画像を文字認識して、`.meter-state.json` に一度だけ取り込みました。取り込んだのは保存済みでない日だけで、このデータはリポジトリに含めていません。推しPメーターと重なる2026年9〜11月の12,852件は、すべて推しPメーターの丸め（0.1K）の範囲で一致しました。早見表の誤記（別の月の表や同じ値の重複）と判断した月・日は除いています。更新スクリプトは LIVER CAMPUS からは取得しません。

精度計算のセルフテストは次で実行します。

```sh
.venv/bin/python -B test_meter_model.py
```

## 更新のタイミング

`update_meter.py` を cron で毎日 0:25 と 12:25（JST）に実行します。

```cron
25 0,12 * * * /path/to/meter/.venv/bin/python -B /path/to/meter/update_meter.py
```

更新には、各ランク・締め時間で直近30日間の実績が7件以上あることが必要です。条件を満たさない場合は予測を作り直さず、前回生成した予測の表示を続けます。最新の実績が4日より古い場合は `stale` として、取得できた最新の実績で予測を作り直します。結果は `status.json` の `state` に記録します。

| `state` | 意味 | ページの表示 |
| --- | --- | --- |
| `ok` | 更新に成功しました。 | 保存済みの予測を表示 |
| `stale` | 更新しましたが、データ元に4日以内の実績がない系列があります。 | データ元の更新待ち |
| `delayed` | 取得・解析・検証のいずれかに失敗しました。 | データの更新に失敗しました |
| `bootstrap` | 初回構築用の `--seed` で生成しました。 | 保存済みの予測を表示 |

## 予測方法

既定の予測は、直近30日間の実績の中央値に曜日の傾向を掛けたものです。曜日の傾向は過去56日間の実績から求め、同じ曜日の観測が少ないほど調整幅を小さくします。30日は月初から月末までの上下を1周分含むため、2022年6月以降の実績で7〜21日より誤差が小さくなりました。

予測値には、全体の水準と月初・月末・休日の補正を加えます。曜日別予測を過去400日の各日について計算し直し、その誤差を全ランクで平均したものを、定数項（全体の水準のずれ）と、締め区間が月初3日間・月末2日間・祝日などの休日・お盆・年末年始に重なる割合で回帰して求めます。2026年11月23日時点の推定値は、水準 −3.2%、月初 +3.1%、月末 +5.9% です。イベントの種類別の補正は、検証で精度が下がったため使っていません（「予測精度」の節を参照）。

休日は、締め区間（締め時刻までの24時間）と重なる時間の割合で扱います。24時締めはその日の0時〜24時なので、祝日当日の24時締めは祝日、祝日前日の24時締めは平日です。13時・22時締めは前日の13時・22時からの24時間なので、祝日の翌日の13時・22時締めも、祝日と重なる時間（11時間・2時間）の割合だけ休日として扱います。

さらに、ランク別の補正を掛けます。上の補正で残った過去365日の誤差を、ランク・締め時間・ボーダー・曜日・日付（月の何日目か、月末までの日数）・曜日の傾向・休日から LightGBM（決定木を重ねる勾配ブースティング）で学習し、予測した補正の75%を使います。補正の割合はランク・ボーダー・日付ごとに変わります。2026年11月24日時点の今日の予測では、たとえば D1 13時締めが −6〜−7%、S6 24時締めの +2 が +10% です。ページでは各ボーダーの根拠に「水準・月初・月末・休日 ±X%」「ランク別 ±X%」と、それぞれのポイントを表示します。曜日別以外の方式（正則化回帰・イベント回帰）が選ばれた系列には、ランク別補正を掛けません。

予測には、過去90日の予測誤差のうち中央の85%から求めた範囲を付けます。2025年4月〜2026年11月の検証では、実績の82%（2026年9〜11月は78%）がこの範囲に入りました。

同じ予測条件で比較できる実績が24日分以上たまると、中央値・曜日別・正則化回帰・イベント回帰のうち、その系列で誤差が最も小さい方式を自動で選びます。予測は当日から45日先まで作ります。

## 技術的な詳細

### 締め区間と公開の遅れ

日付 d・h 時締めの締め区間は、前日の h 時から d の h 時までの24時間です（`day_window`）。24時締めは d の0時〜24時です。祝日・月初・月末などは、締め区間と重なる時間の割合（0〜1）として扱います（`window_share`、`vacation_features`）。

実績は締めの2日後に公開されるとみなします（`PUBLISH_LAG`）。過去の予測を作り直すときは、締め区間が始まる時点で公開済みだった実績だけを使います（`replay`）。

### 予測の式

```text
予測 = 基準値 × 曜日係数 × exp(水準・月初・月末・休日の補正) × exp(0.75 × ランク別補正)
```

補正は順に掛け、そのたびにポイントを整数に丸めます。補正後に ±0 ≤ +1 ≤ +2 の順が崩れた日は、3つとも補正なしの30日中央値に戻します。

- **基準値**（`baseline`）：直近30日間（`BASELINE_DAYS`）の実績の中央値です。ボーダーごとに計算します。
- **曜日係数**（`weekly_offsets`、`weekday_factors`）：
  - 過去56日（`WEEKDAY_HISTORY`）の各日について、値の対数から同じ週の中央値を引きます。4日以上観測がある週だけを使います。
  - 曜日ごとに、その差の中央値 m を求めます。
  - 観測した週の数を n として `exp(m × n ÷ (n + 4))` とします（`WEEKDAY_SHRINKAGE`）。観測が少ないほど 1 に近づきます。
  - 同じ曜日の観測が2週未満（`WEEKDAY_MIN_WEEKS`）の系列は、同じ締め時間・ランク帯の値を使います。
- **45日先まで同じ式で計算します**：直近7日・前日・前週の値のような入力は1〜3日先にしか使えないため、入れていません。

### 水準・月初・月末・休日の補正（`corrections`）

1. 過去400日（`MODEL_HISTORY`）の各日について、補正前の式で予測を作り直します。
2. 誤差 `log(実績 ÷ 予測)` を、締め区間（日付・締め時間）ごとに全ランク・全ボーダーで平均します。全ランク共通の動きだけを学ぶためです。
3. この平均誤差をリッジ回帰（`fit_ridge`）で説明します。罰則は 4（`RIDGE_PENALTY`）で、定数項には罰則を掛けません。

| 説明変数 | 内容 |
| --- | --- |
| 定数項 | 全体の水準のずれ |
| 月末 | 締め区間のうち、月末2日間（`MONTH_END_DAYS`）に重なる割合 |
| 月初 | 締め区間のうち、月初3日間（`MONTH_START_DAYS`）に重なる割合 |
| 休日・休暇 | 祝日・振替休日・お盆・年末年始のいずれかに重なる割合 |
| お盆 | 8月13〜16日に重なる割合 |
| 年末年始 | 12月29日〜1月3日に重なる割合 |

推定値は `data.json` の `contextTraining` に入ります（`levelPercent`、`monthStartPercent`、`monthEndPercent`）。値は締め区間がすべて重なった場合の補正（%）です。

### ランク別補正（`rank_model`、`rank_features`）

LightGBM で、上の補正を掛けたあとに残った誤差 `log(実績 ÷ 補正後の予測)` を学習します。学習データは過去365日（`RANK_HISTORY`）・54系列・3ボーダー分で、2026年11月24日時点で約5.7万件です。

LightGBM は決定木を順に300本作り、それぞれの木がそれまでの木で残った誤差を少しずつ埋めます。決定木を使うのはこのランク別補正だけです。30日中央値と曜日係数は中央値を取るだけの統計で、水準・月初・月末・休日の補正はリッジ回帰です。補正なしの予測に LightGBM を直接掛ける方式は、2026年9〜11月の誤差が悪化したため使っていません（「予測精度」の試した方法の表を参照）。

| 説明変数 | 内容 |
| --- | --- |
| ランク | D1〜S6 の番号 |
| 締め時間 | 13、22、24 |
| ボーダー | 0（±0）、1（+1）、2（+2） |
| 曜日 | 0（月）〜6（日） |
| 日 | 1〜31 |
| 月末までの日数 | 月末の日が 1 |
| 曜日係数の対数 | 曜日係数の強さ |
| 休日・休暇、お盆、年末年始 | 締め区間に重なる割合 |
| 祝日 | その日付が祝日・振替休日なら 1 |

| 設定 | 値 |
| --- | --- |
| 目的関数 | `regression`（二乗誤差） |
| 木の数 / 学習率 | 300 / 0.03 |
| 葉の数 / 葉の最小件数 | 31 / 200 |
| 行・列の抽出 | `bagging_fraction` 0.8（毎回）、`feature_fraction` 0.8 |
| 乱数・スレッド | `seed` 0、1スレッド |

- **75%を掛ける理由**：予測した補正のうち 75%（`RANK_SHARE`）だけを掛けます。選定期間で 50%・75%・100% を比べ、75%が最良でした。
- **2回学習する理由**：更新のたびに2回学習します。
  - 1回目は直近までの365日で学習し、公開する予測に使います。
  - 2回目は直近90日より前の365日で学習します。直近90日の「過去データで再現」の精度と予測の範囲を、学習に使っていないデータで計算するためです。
- **掛けない系列**：曜日別以外の方式（中央値・正則化回帰・イベント回帰）が選ばれた系列には掛けません。

### 予測の範囲（`spread`）

1. 直近90日（`VALIDATION_HISTORY`）の補正後の予測について、`実績 ÷ 予測` を並べます。
2. 7.5%点と92.5%点（中央の85%）を予測に掛けます。
3. 件数が20未満の系列は、同じ締め時間の全ランクの値を使います。

過去の誤差から作った幅は先の日には少し狭いため、85%にすると先の日の約8割（`RANGE_SHARE`）が入ります。

### 方式の自動選択（`evaluate`、`select_model`）

同じ予測条件で比べられる実績が24日分（`MIN_TEST`）以上ある系列では、次の誤差を比べます。

- 中央値
- 曜日別予測
- 曜日・休日を使う正則化回帰（`build_models`）

公式イベントの記録が十分にあれば（イベントのある日・ない日が各8日以上、`MIN_EVENT_TEST`）、イベント回帰も比べます。比べるときは、締め区間が始まる時点で確認済みだったイベント情報だけを使います。

### 時系列の検証

「予測精度」の節の数値は、次の手順で計算しました。

1. 毎月はじめに、その時点で公開済みだった実績だけで補正とランク別補正を学び直します。
2. その月の各日を予測します。
3. 方式と設定は2025年1月〜2026年8月の結果だけで選び、2026年9〜11月は最後の確認にだけ使いました。

## 予測精度

更新のたびに、各ランク・締め時間・ボーダーについて次の2種類の精度を計算します。結果はページの「予測方法と検証結果」、API の `accuracy`、`data.json` に入ります。

| 種類 | キー | 内容 |
| --- | --- | --- |
| 過去データで再現 | `replay` | 過去の各日について、締め区間が始まる時点で公開済みだった実績だけを使い、曜日別予測を計算し直した結果です。実績は締めの2日後に公開されたとみなします（`publishLagDays`）。直近90日が対象で、水準・月初・月末・休日の補正とランク別補正を含みます。水準・月初・月末・休日の補正は対象の90日を含む過去400日から推定するため少し良い値に、ランク別補正は対象の90日より前の誤差だけで学習するため少し悪い値になります。 |
| 公開した予測 | `published` | このサイトが実際に表示した予測と、その後の実績の比較です。直近30日が対象で、運用を続けるほど件数が増えます。 |

各値の意味は次のとおりです。比較できる実績がない場合は `{"n": 0}` だけを返します。

| キー | 内容 |
| --- | --- |
| `n` | 比較した日数（全体では件数） |
| `mape` | 平均絶対割合誤差（%）。予測と実績の差を実績で割った値の平均です。 |
| `within10` / `within20` | 誤差が ±10% / ±20% 以内だった割合（%） |
| `bias` | 誤差の平均（%）。プラスなら予測が実績より高めです。 |

### 検証結果（2026年11月24日時点）

2025年1月〜2026年11月19日の全54系列・3ボーダー（108,336件）で、現在の方式を検証しました。各月のはじめに、その時点で公開済みだった実績だけで補正とランク別補正を学習し直し、その月の各日の予測を再現しています。2026年8月以前の実績は、LIVER CAMPUS の早見表から取り込んだものです（「ローカルで動かす」の節を参照）。

| 期間 | 平均誤差（MAPE） | ±10%以内 | ±20%以内 | 偏り |
| --- | --- | --- | --- | --- |
| 2025年 | 10.5% | 63% | 85% | +0.7% |
| 2026年1〜11月 | 10.6% | 63% | 84% | +1.3% |
| 2026年9〜11月 | 11.7% | 58% | 80% | +3.6% |

方式を決めるときは、2025年1月〜2026年8月の結果だけで比べ、2026年9〜11月は最後の確認だけに使いました。

| 方式 | 2025年1月〜2026年8月 | 2026年9〜11月 |
| --- | --- | --- |
| 30日中央値 × 曜日（補正なし） | 11.01% | 12.20% |
| ＋ 水準・月初・月末・休日の補正 | 10.98% | 11.79% |
| ＋ ランク別補正（LightGBM、現在の方式） | **10.36%** | **11.67%** |

2022年6月以降の実績で比べると、基準の中央値は14日より30日の方が誤差が小さくなりました（2022年6月〜で14.3% → 13.7%、補正なし）。前回までは2026年10〜11月の約6週間だけで方式を決めていたため、14日を選んでいました。

水準の補正は、予測が全体に高めに出る傾向（2026年11月時点で約3%）を直します。月初の上振れは年々小さくなっています。月初3日間の実績は、30日中央値の予測に比べて2022年は11.5%、2023年は9.1%、2024年は4.5%、2025年は2.5%、2026年は1.0%高めでした（中央値）。補正は過去400日から学び直すため、この変化に追従します。

ランク別補正の LightGBM は、次の点を調整しました。

- 誤差の二乗を小さくする学習（`regression`）にしました。絶対誤差（`l1`）で学習すると、誤差の中央値（ほぼ0%）しか学ばず、2026年9〜11月の全体的な下振れを直せませんでした（12.15%）。
- 水準・月初・月末・休日の補正の上に重ね、予測した補正の75%だけを使います。100%では2026年9〜11月が11.84%、50%では11.60%で、選定期間では75%が最良でした。
- 直近7日・前日・前週の値や、直近の誤差を入力に加えても改善しなかったため、使っていません。これらは1〜3日先にしか使えないため、45日先までの予測にも向きません。日付を5区分（1〜3日、4〜10日、11〜20日、21日〜月末3日前、月末2日間）にまとめると、2026年9〜11月はわずかに良く（11.60%）、選定期間は悪くなりました（10.54%）。
- 学習期間は365日です。730日や、新しい日を重く見る重み付け、2週間ごとの学習でも改善しませんでした。

区分ごとの誤差は次のとおりです（2025年1月〜2026年11月、現在の方式）。

| 区分 | MAPE | 偏り | 補足 |
| --- | --- | --- | --- |
| 月・火 | 9.8% / 10.3% | +1.0% / +1.2% | |
| 水・木 | 11.0% / 10.9% | +1.5% / +1.4% | |
| 金〜日 | 10.5〜10.7% | +0.1〜+1.0% | |
| 月初3日間 / 月末2日間 | 9.3% / 9.9% | +0.3% / −1.2% | 補正後は他の日と同程度です。 |
| 祝日 | 10.2% | +1.4% | |
| 13時 / 22時 / 24時締め | 10.9% / 10.4% / 10.2% | +0.7% / +0.9% / +1.2% | |
| D帯 / C帯 / B帯 / A帯 / S帯 | 12.4% / 7.4% / 8.5% / 8.7% / 13.1% | +0.6〜+1.4% | |
| S6 の +1・+2 | 21.4% | +5.3% | 最も外れやすい系列です。 |
| ±0 / +1 / +2 | 11.8% / 9.7% / 10.0% | +0.6〜+1.3% | |

大きい順で上位1割の誤差が全体の33%を占めます。前後3日の実績の中央値（未来の値を使う理想的な予測）の MAPE は7.9%で、現在の10.5%との差は2.6ポイントです。次の方法も試しました。

| 試した方法 | 2025年1月〜2026年8月 | 2026年9〜11月 | 採用しない理由 |
| --- | --- | --- | --- |
| 現在の方式 | 10.36% | 11.67% | |
| 補正なしの30日中央値 × 曜日に LightGBM（絶対誤差で学習） | 10.20% | 12.12% | 直近3か月が悪化しました。 |
| 補正なしの30日中央値 × 曜日に LightGBM（二乗誤差で学習） | 10.30% | 11.84% | 直近3か月が現在の方式より悪くなりました。 |
| ランクごとの一律の補正（過去の誤差の平均） | 11.08% | 11.85% | 補正なしより悪くなりました。 |
| イベントの種類別の補正 | — | 12.3% → 13.3〜13.6%（2026年10〜11月） | 週ごとに効果の向きが変わりました。2026年8月以前のイベント一覧は取得していないため、長期では検証していません。 |

## JSON API と CSV

| パス | 内容 |
| --- | --- |
| `api.php` | 対象期間、対応ランク、締め時間、リクエスト例を返します。 |
| `api.php?date=YYYY-MM-DD&rank=B1&close=13` | 指定した日付・ランク・締め時間の予測、実績、予測精度、イベント情報を返します。 |
| `api-csv.php` | データ上の当日について、全ランク・全締め時間を CSV で返します。`date`、`rank`、`close` で絞り込めます。 |
| `data.json` | 全系列の予測・実績・精度をまとめたデータです。 |
| `status.json` | 最後の更新の時刻と結果です。 |

API は GET と HEAD に対応し、どのオリジンからも呼び出せます（`Access-Control-Allow-Origin: *`）。

### パラメーター

| 名前 | 値 |
| --- | --- |
| `date` | `YYYY-MM-DD`。`api.php` の `dateRange`（過去30日〜45日先）の範囲内です。 |
| `rank` | `D1`〜`D3`、`C1`〜`C3`、`B1`〜`B3`、`A1`〜`A3`、`S1`〜`S6` |
| `close` | `13`、`22`、`24` |

### レスポンス

```json
{

  "date": "2026-11-22",
  "rank": "B1",
  "closingHour": 22,
  "window": {"start": "2026-11-21T22:00:00+09:00", "end": "2026-11-22T22:00:00+09:00", "timezone": "Asia/Tokyo"},
  "forecast": {

                     "weekday": {"n": 7, "shared": false, "percent": 0.0, "provisional": true},
                     "context": {"holiday": -3300, "rank": 950, "events": 0, "holidayPercent": -3.1, "rankPercent": 0.9}}, "...": "..."}
  },
  "actual": null,
  "accuracy": {
    "replay": {"±0": {"n": 41, "mape": 12.1, "within10": 56, "within20": 73, "bias": 5.9}, "...": "..."},
    "published": {"±0": {"n": 0}, "...": "..."}
  },
  "holidays": [],
  "events": {"scheduleAvailable": true, "missingMonths": [], "officialSimultaneousHours": 0, "items": ["..."]},
  "update": {"forecastAt": "...", "observationsAt": "...", "latestActualDate": "2026-11-19",
             "lastAttemptAt": "...", "lastAttemptState": "ok", "failed": false,
             "holidayUpdateFailed": false, "referenceEventUpdateFailed": false},
  "sources": {"observations": "https://www.oshi-p-meter.com/borders/B1/22", "...": "..."}

```

| キー | 内容 |
| --- | --- |
| `window` | 締め区間。締め時刻の24時間前から締め時刻までです。 |
| `forecast` | ボーダーごとの予測ポイントと根拠です。予測を公開していない過去の日は `null` です。 |
| `forecast.range` | 実績の約8割が入る範囲 `[下限, 上限]`（ポイント）です。過去の誤差が足りない場合は `null` です。 |
| `forecast.basis.*.method` | `weekday`（曜日別）、`median`（直近30日中央値）、`source_median`（公開30日中央値）、`ridge`（正則化回帰）、`events`（イベント回帰） |
| `forecast.basis.*.context` | 補正で加えたポイントと割合です。`holiday` は水準・月初・月末・休日の補正、`rank` はランク別補正、`events` はイベント補正のポイントです。`holidayPercent`・`rankPercent` はそれぞれの補正の割合（%）です。イベント補正は現在使っておらず、常に `0` です。2026年11月24日より前に公開した予測には `rank` と割合がありません。 |
| `actual` | 公開済みの実績です。締め前や未掲載の日は `null` です。 |
| `accuracy` | その系列の予測精度です。内容は「予測精度」の節のとおりです。 |
| `holidays` / `events` | 締め区間に重なる祝日・休暇と、イベントです。 |
| `update.failed` | 最後の更新が失敗（`delayed`）した場合に `true` です。データ元の遅れは `lastAttemptState` が `stale` になります。 |

### エラー

エラー時は `{"apiVersion": 1, "error": {"code": "...", "message": "..."}}` を返します。

| HTTP | `code` | 原因 |
| --- | --- | --- |
| 400 | `invalid_query` / `invalid_date` / `invalid_rank` / `invalid_close` | パラメーターがない、または値が正しくありません。 |
| 404 | `date_out_of_range` | 日付が保存データの範囲外です。`dateRange` を返します。 |
| 405 | `method_not_allowed` | GET・HEAD 以外のメソッドです。 |
| 503 | `snapshot_unavailable` | `data.json` を読み込めません。 |

### CSV

`api-csv.php` は UTF-8（BOM 付き）、改行 CRLF の CSV を返します。1行が1つのボーダーです。`border` は `0`（±0）、`1`（+1）、`2`（+2）です。`holiday_names`、`event_names`、`missing_event_months` は JSON 配列の文字列です。`provisional` は、補正・暫定の曜日傾向・公開30日中央値のいずれかを使った予測なら `1` です。`holiday_adjustment_points` は水準・月初・月末・休日の補正です。`forecast_low`・`forecast_high` は予測の範囲、最後の3列 `rank_adjustment_points`・`holiday_adjustment_percent`・`rank_adjustment_percent` はランク別補正のポイントと、各補正の割合（%）です。
