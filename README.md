# POCOMeter

Pococha のランクメーターの非公式予測ツールです。D1〜S6 の各ランクと 13 時・22 時・24 時の締め時間について、±0・+1・+2 に必要な応援ポイントの予測と、取得済みの公開実績を表示します。日付と締め時間は日本時間（JST）です。

## ローカルで動かす

Python 3.9 以降と PHP 8.1 以降が必要です。データの更新には Unix 系の環境と、外部のデータ取得元への接続が必要です。リポジトリのルートで次を実行します。

```sh
python3 -B update_meter.py
php -S 127.0.0.1:8000
```

ブラウザーで `http://127.0.0.1:8000/` を開きます。更新スクリプトは予測と実績を `data.json` に、更新状況を `status.json` に保存します。`events.json` は手動で確認した公式イベント情報です。

取得した実績は `.meter-state.json` にすべて保存し、古いものも削除しません。毎回の更新では、各ランク・締め時間について当月のページを1回ずつ取得し、新しい日と値が変わった日だけを追加します。前月のページを取得するのは、月初5日までと初回構築のときだけです。

精度計算のセルフテストは次で実行します。

```sh
python3 -B test_meter_model.py
```

## 更新のタイミング

`update_meter.py` を cron で毎日 0:25 と 12:25（JST）に実行します。

```cron
25 0,12 * * * /usr/bin/python3 -B /path/to/meter/update_meter.py
```

更新には、各ランク・締め時間で直近30日間の実績が7件以上あることが必要です。条件を満たさない場合は予測を作り直さず、前回生成した予測の表示を続けます。最新の実績が4日より古い場合は `stale` として、取得できた最新の実績で予測を作り直します。結果は `status.json` の `state` に記録します。

| `state` | 意味 | ページの表示 |
| --- | --- | --- |
| `ok` | 更新に成功しました。 | 保存済みの予測を表示 |
| `stale` | 更新しましたが、データ元に4日以内の実績がない系列があります。 | データ元の更新待ち |
| `delayed` | 取得・解析・検証のいずれかに失敗しました。 | データの更新に失敗しました |
| `bootstrap` | 初回構築用の `--seed` で生成しました。 | 保存済みの予測を表示 |

## 予測方法

既定の予測は、直近14日間の実績の中央値に曜日の傾向を掛けたものです。曜日の傾向は過去56日間の実績から求め、同じ曜日の観測が少ないほど調整幅を小さくします。

予測値には月末・休日の補正を加えます。曜日別予測を過去400日の各日について計算し直し、その誤差を全ランクで平均したものを、締め区間が月末2日間・祝日などの休日・お盆・年末年始に重なる割合で回帰して求めます。全体的な偏りは補正しません。過去の誤差から学んでも、その後の偏りを予測できなかったためです。イベントの種類別の補正は、検証で精度が下がったため使っていません（「予測精度」の節を参照）。

予測には、過去90日の予測誤差のうち中央の85%から求めた範囲を付けます。2026年10〜11月の検証では、実績の約80%がこの範囲に入りました。

同じ予測条件で比較できる実績が24日分以上たまると、中央値・曜日別・正則化回帰・イベント回帰のうち、その系列で誤差が最も小さい方式を自動で選びます。予測は当日から45日先まで作ります。

## 予測精度

更新のたびに、各ランク・締め時間・ボーダーについて次の2種類の精度を計算します。結果はページの「予測方法と検証結果」、API の `accuracy`、`data.json` に入ります。

| 種類 | キー | 内容 |
| --- | --- | --- |
| 過去データで再現 | `replay` | 過去の各日について、締め区間が始まる時点で公開済みだった実績だけを使い、曜日別予測を計算し直した結果です。実績は締めの2日後に公開されたとみなします（`publishLagDays`）。直近90日が対象で、休日・イベントの暫定補正は含みません。 |
| 公開した予測 | `published` | このサイトが実際に表示した予測と、その後の実績の比較です。直近30日が対象で、運用を続けるほど件数が増えます。 |

各値の意味は次のとおりです。比較できる実績がない場合は `{"n": 0}` だけを返します。

| キー | 内容 |
| --- | --- |
| `n` | 比較した日数（全体では件数） |
| `mape` | 平均絶対割合誤差（%）。予測と実績の差を実績で割った値の平均です。 |
| `within10` / `within20` | 誤差が ±10% / ±20% 以内だった割合（%） |
| `bias` | 誤差の平均（%）。プラスなら予測が実績より高めです。 |

### 検証結果（2026年11月22日時点）

2026年10月10日〜11月19日の全54系列・3ボーダー、6,534件を「過去データで再現」で検証した結果です。

| 平均誤差（MAPE） | ±10%以内 | ±20%以内 | 偏り |
| --- | --- | --- | --- |
| 12.3% | 56% | 79% | +4.2% |

基準の中央値を30日から14日に短くしたことで、誤差は次のように下がりました。この表は、公開の遅れを考えずに前日・数日前時点の予測を比べたものです。

| 予測した時点 | 30日中央値 | 14日中央値 |
| --- | --- | --- |
| 前日 | 12.7% | 12.0% |
| 3日前 | 13.2% | 12.6% |
| 7日前 | 14.0% | 13.6% |
| 14日前 | 15.6% | 15.4% |

誤差の主な原因は、全ランクで同時に起きる水準の上下です。10月30〜31日（月末）は通常より11〜13%高く、予測は8〜12%低すぎました。11月4〜12日は5〜10%低く、予測は10〜14%高すぎました。大きい順で上位1割の誤差が全体の32%を占め、その多くがこの時期に集まっています。直近の全体の水準で補正しても改善しませんでした（12.25% → 12.23%）。実績の公開が遅れるため、水準の変化はデータが届く前に始まっています。

| 区分 | MAPE | 偏り | 補足 |
| --- | --- | --- | --- |
| 月〜木 | 11.2〜12.2% | +4.2〜+6.9% | 予測が高めです。 |
| 金〜日 | 12.6〜12.9% | +0.8〜+2.3% | 実績が予測を20%以上上回る日が11〜13%あり、月〜木の約3倍です。 |
| 祝日を含む区間 | 10.5% | +3.4% | 祝日を含まない区間は12.4%です。 |
| 13時 / 22時 / 24時締め | 11.4% / 12.4% / 12.9% | +2.9% / +3.9% / +5.6% | |
| A帯 / S帯 | 10.4% / 13.6% | +4.2% / +3.5% | S6 の +1・+2 は24〜29%です。 |

ほぼ毎日（98%）期間の短いイベントが4件以上同時に開かれているため、イベントの有無では比較できません。イベントの種類別の MAPE は11.0〜13.2%で、全体との差は小さいです。誤差が大きかった個別のイベントは11月4〜12日の水準低下と重なっており、イベント自体の影響とは区別できません。曜日の補正を強めると悪化したため（12.3% → 12.8%）、週末の伸びは毎週決まったものではないと考えられます。

実績は日ごとの上下が大きく、前後3日の実績の中央値（未来の値を使う理想的な予測）でも MAPE は10.8%です。現在の12.3%との差は1.5ポイントで、実績だけを使う予測で縮められる余地は小さいです。次の方法も試しましたが、精度は上がりませんでした。

| 試した方法 | MAPE（補正なし 12.25%） |
| --- | --- |
| 休日・イベントの暫定補正（公開中の予測に含まれます） | 12.34% |
| 直近の全体の水準で補正 | 12.23% |
| 過去の誤差から学習した偏りの補正 | 12.25% |
| 曜日の補正を強める | 12.8% |

予測を一律3%下げると11.9%になりますが、これは11月の水準低下を後から知っている場合の値です。その時点までの誤差だけで偏りを学習すると改善しません。

検証期間は約6週間で、月末は1回しか含みません。

## JSON API と CSV

| パス | 内容 |
| --- | --- |
| `api.php` | 対象期間、対応ランク、締め時間、リクエスト例を返します。 |
| `api.php?date=YYYY-MM-DD&rank=B1&close=13` | 指定した日付・ランク・締め時間の予測、実績、予測精度、イベント情報を返します。 |
| `api-csv.php` | データ上の当日について、全ランク・全締め時間を CSV で返します。`date`、`rank`、`close` で絞り込めます。 |
| `data.json` | 全系列の予測・実績・精度をまとめたデータです。 |
| `status.json` | 最後の更新の時刻と結果です。 |

API は GET と HEAD に対応し、どのオリジンからも呼び出せます（`Access-Control-Allow-Origin: *`）。

### パラメーター

| 名前 | 値 |
| --- | --- |
| `date` | `YYYY-MM-DD`。`api.php` の `dateRange`（過去30日〜45日先）の範囲内です。 |
| `rank` | `D1`〜`D3`、`C1`〜`C3`、`B1`〜`B3`、`A1`〜`A3`、`S1`〜`S6` |
| `close` | `13`、`22`、`24` |

### レスポンス

```json
{
  "apiVersion": 1,
  "date": "2026-11-22",
  "rank": "B1",
  "closingHour": 22,
  "window": {"start": "2026-11-21T22:00:00+09:00", "end": "2026-11-22T22:00:00+09:00", "timezone": "Asia/Tokyo"},
  "forecast": {
    "points": {"±0": 105293, "+1": 198027, "+2": 295068},
    "range": {"±0": [81286, 120982], "...": "..."},
    "basis": {"±0": {"method": "weekday", "n": 12, "from": "2026-11-08", "through": "2026-11-21", "source": null,
                     "weekday": {"n": 7, "shared": false, "percent": 0.0, "provisional": true},
                     "context": {"holiday": 0, "events": 0}}, "...": "..."}
  },
  "actual": null,
  "accuracy": {
    "replay": {"±0": {"n": 41, "mape": 12.1, "within10": 56, "within20": 73, "bias": 5.9}, "...": "..."},
    "published": {"±0": {"n": 0}, "...": "..."}
  },
  "holidays": [],
  "events": {"scheduleAvailable": true, "missingMonths": [], "officialSimultaneousHours": 0, "items": ["..."]},
  "update": {"forecastAt": "...", "observationsAt": "...", "latestActualDate": "2026-11-19",
             "lastAttemptAt": "...", "lastAttemptState": "ok", "failed": false,
             "holidayUpdateFailed": false, "referenceEventUpdateFailed": false},
  "sources": {"observations": "https://www.oshi-p-meter.com/borders/B1/22", "...": "..."}
}
```

| キー | 内容 |
| --- | --- |
| `window` | 締め区間。締め時刻の24時間前から締め時刻までです。 |
| `forecast` | ボーダーごとの予測ポイントと根拠です。予測を公開していない過去の日は `null` です。 |
| `forecast.range` | 実績の約8割が入る範囲 `[下限, 上限]`（ポイント）です。過去の誤差が足りない場合は `null` です。 |
| `forecast.basis.*.method` | `weekday`（曜日別）、`median`（直近14日中央値）、`source_median`（公開30日中央値）、`ridge`（正則化回帰）、`events`（イベント回帰） |
| `forecast.basis.*.context` | 補正で加えたポイントです。`holiday` は月末・休日の補正、`events` はイベント補正です。イベント補正は現在使っておらず、常に `0` です。 |
| `actual` | 公開済みの実績です。締め前や未掲載の日は `null` です。 |
| `accuracy` | その系列の予測精度です。内容は「予測精度」の節のとおりです。 |
| `holidays` / `events` | 締め区間に重なる祝日・休暇と、イベントです。 |
| `update.failed` | 最後の更新が失敗（`delayed`）した場合に `true` です。データ元の遅れは `lastAttemptState` が `stale` になります。 |

### エラー

エラー時は `{"apiVersion": 1, "error": {"code": "...", "message": "..."}}` を返します。

| HTTP | `code` | 原因 |
| --- | --- | --- |
| 400 | `invalid_query` / `invalid_date` / `invalid_rank` / `invalid_close` | パラメーターがない、または値が正しくありません。 |
| 404 | `date_out_of_range` | 日付が保存データの範囲外です。`dateRange` を返します。 |
| 405 | `method_not_allowed` | GET・HEAD 以外のメソッドです。 |
| 503 | `snapshot_unavailable` | `data.json` を読み込めません。 |

### CSV

`api-csv.php` は UTF-8（BOM 付き）、改行 CRLF の CSV を返します。1行が1つのボーダーです。`border` は `0`（±0）、`1`（+1）、`2`（+2）です。`holiday_names`、`event_names`、`missing_event_months` は JSON 配列の文字列です。`provisional` は、補正・暫定の曜日傾向・公開30日中央値のいずれかを使った予測なら `1` です。`holiday_adjustment_points` は月末・休日の補正です。最後の2列 `forecast_low`・`forecast_high` は予測の範囲です。
